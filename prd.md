# Product requirements — Utility Bill Decoder

## Source and objective
Source of truth: [WTQ Build Track Participant Guide](https://drive.google.com/file/d/1FIzOuil-oJ2nuiempoMDkZojyRivzI1U/view), sections 1–9. Build an AI-powered Python 3.11+ CLI that processes scanned/photo/screenshot electricity bills from K-Electric (KE), LESCO and IESCO. It must complete the organizer's two CSV templates programmatically and produce a reproducible submission ZIP. AI-assisted coding is allowed; disclose every AI coding tool in the submission README.

## Deadline and success criteria
All times Pakistan Standard Time, 10 October 2026. Train set: five images available at 10:30. Test set: 10 images and two templates at 12:30. Upload **one ZIP by 13:30** to https://build.womentechquest.com/submit; **no resubmission**. ZIP at most 15 MB. Base scoring: extraction 30, answers 30, engineering 15, AI design 15, reproducibility 10; optional demonstration up to +5. A strong result needs both high accuracy and an executable workflow, not just a polished interface. There is no promise of full marks.

## Inputs
- `train/bills/`: IESCO_0004.jpg, KESC_0004.png, KESC_0008.png, LESCO_0005.png, LESCO_0006.png. No training answer files; section 5.7 gives the correct Level 1 output for KESC_0008.
- `test/bills/`: 10 unseen PNG/JPG images, released at 12:30.
- `test/csv/level1.csv`: columns `bill_id,json`, 10 rows.
- `test/csv/level2.csv`: columns `bill_id,question_id,question,answer`, 120 rows, 12 questions per bill. Actual questions are released at 12:30. Never hard-code the guide's two examples as the test questions.
- `bill_id` is the image filename without extension; KESC filenames represent provider `KE` in output.

## Level 1 acceptance
Exactly one JSON object in the `json` cell for every original Level 1 row. Include all keys, even when values are null:
```json
{"provider":null,"tariff":null,"sanctioned_load_kw":null,"bill_month":null,"reading_date":null,"issue_date":null,"due_date":null,"previous_reading":null,"current_reading":null,"units_consumed":null,"charges":[],"total_charges":null,"taxes":[],"total_taxes":null,"current_bill":null,"arrears":null,"payable_within_due_date":null,"payable_after_due_date":null}
```
Provider is one of KE, LESCO, IESCO; `bill_month` YYYY-MM; dates YYYY-MM-DD; numeric fields JSON numbers. Charge item: `{"type": ..., "amount": number}` with types energy, fixed, fpa, quarterly_adjustment, surcharge, meter_rent, subsidy, other. Tax item types gst, electricity_duty, income_tax, municipal_tax, other_tax. Preserve distinct nonzero printed lines and printed subtotals, even if arithmetic appears inconsistent. Classify by printed section, not label; tax-section TV fee is other_tax. Credits, CR and subsidies are negative; blank, covered, absent or unreadable is null; empty list is []. Never output personal names, addresses, CNICs, account/reference/consumer/meter numbers.

## Level 2 acceptance
Exactly one nonempty English answer per original question row, grounded in that bill. Use the source image and extracted nonidentifying values, including history charts that do not fit the Level 1 schema. Calculate averages, counts, differences and percentages with code where feasible; explain the numerator, denominator, units and time window. Label estimates and state the calculation. For absent values, say the bill does not provide the information. If wording is ambiguous, state an interpretation or answer both. Do not import tariffs or facts from outside the image.

## CSV and submission contract
Preserve original headers, row order and `bill_id`, `question_id`, `question` exactly. Use Python's `csv` module, UTF-8, and compact one-line JSON. No empty `json` or `answer` cells. Results must be generated by the program from organizer templates; manual filling is invalid.
```text
submission.zip
├── output/level1.csv
├── output/level2.csv
├── source/README.md
├── source/.env.example
├── source/requirements.txt
├── source/...(all runnable project code)
└── demo/demo.mp4   (optional, <=3 minutes)
```
Never include the real `.env` or API keys. The source README must give Python version, exact setup and run commands, dependencies, and an AI usage section naming every runtime model/API/service and every AI coding assistant actually used; write `none` for categories unused.

## Constraints and priorities
Runtime LLMs only: Claude Haiku 4.5, Gemini 3.5 Flash-Lite, Gemini 3.1 Flash-Lite, GPT-4.1 mini, GPT-5 mini. Existing successful key uses free `gemini-3.5-flash-lite`; no paid model is necessary. No Azure services or invoice/receipt extraction agents (including Azure prebuilt-invoice, Textract AnalyzeExpense or Mindee). Local OCR libraries are allowed. Free Gemini tier in guide: 15 requests/minute, 250K tokens/minute and 500/day; code must pace calls, retry rate limits and save partial progress. Prioritize valid 10+120 CSVs and verification before optional video or UI.

## Out of scope for submission
Hosting, authentication, persistent customer database, billing advice based on external rates, display of identifiers, and a public production website. A small CLI is enough if it is accurate, robust and demonstrable.
